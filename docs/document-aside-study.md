# 元信息列表与章节导航试验

分支：`codex/document-aside-study`。基线为主题 `20fd260`、站点 `7758224`，本试验尚未合并回 `codex/flatten-navigation`。

## 判断

元信息是文档组件，`list` 是页面展示声明。视觉相似不要求数据和交互协议相同。保留 `feature-document/meta.html`，复用条目图标、链接行和状态颜色；路径保留多个链接，日期保留普通文本。不增加 `list: meta`、Markdown fragment、通用 `type` 分发器或新依赖。

| 方案 | 评价 |
| --- | --- |
| 扩展 choice，增加路径、日期、章节类型 | 会把选择控件扩展成混合信息渲染器，且仍需处理页面声明，职责过大 |
| 为所有列表建立新的行数据协议 | 当前收益不足，需要迁移已有列表并维护更多抽象 |
| 专用文档组件，共用底层视觉 | 本分支采用；保留多链接路径与静态时间的语义，少量局部排版代码可直接理解 |

## 组件边界

- `baseof.html` 提供 `document-aside` 布局 block，默认按原有 `slots.meta` 渲染元信息。
- `page-article.html` 明确传入章节组件；其他页面布局不需要识别文章类型。文章的章节导航独立于 `slots.meta`，例如关于页可以只有章节。
- `feature-document/aside.html` 只负责组合实际非空的元信息和章节内容，没有新 slot、状态仓库或组件注册表。
- `toc.html` / `toc-items.html` 读取 Hugo `.Fragments.Headings`，只取 H2、H3，按正文顺序生成一个平铺列表；不存在这两级标题时不输出空导航和脚本。H1 仍由正文模板所有。
- `.Title` 去掉内联 HTML 后作为目录文字，ID 直接来自 Hugo；不重新解析 Markdown、不重新生成锚点。跳级标题的空容器不会产生空目录项。

官方 API：[Hugo Page.Fragments](https://gohugo.io/methods/page/fragments/)。

## 排版

元信息先显示“更新于…”、“发布于…”两行时间，各用一个 clock 图标，日期相同也保留两行。随后显示全部分类路径，每个叶子一行完整路径；再显示“/ 内容”等目录路径，两类路径统一使用 tag 图标。媒体平台外链放在最后，各一行，GitHub 和公众号按 URL 主机使用已有图标，其余外链使用 link 图标。同类条目相邻排列，所有元信息行保持相同行距，不通过空行或额外间距分组。图标容器占一行文字的高度（`1lh`），复用居中对齐；多行路径的图标始终对齐首行。

路径段保持独立链接。元信息移除整行悬停背景，反馈和键盘焦点只落在实际链接；日期不伪装成可点击控件。章节每行只有一个跳转目标，继续复用 `collection-item-link` 的悬停与当前状态。

“章节”是列表第一项，链接到现有 `#main`，负责文章开头至第一个目录标题之前的区域；点击回到文章顶部。它与 H2、H3 共用链接、悬停、当前项和锚点定位逻辑，无独立标题样式或滚动分支。

章节不输出图标或空白占位节点。“章节”和 H2 顶格，H3 的标题文本区域用 `padding-inline-start: 1em` 缩进约一个汉字，换行续行与首行文字对齐；悬停和当前项背景仍覆盖完整行。列表保持平铺，H4–H6 不显示。

右列独立宽度为 `min(30rem, 100cqi)`，桌面约 450px，左侧导航仍为 225px。极长文字完整换行，续行与文字对齐，不用省略号。加宽会增加画布总宽度，不能保证普通笔记本同时展示所有列。

各列共用页面顶部留白（默认 12px），不添加独立的顶部补偿。根入口、列表列头、文章顶部标题及辅助列使用 1rem 字号和 `--column-line-height: 1.7`，统一首行文字排版。列表横线位于自然行高 `1lh` 之后，标题单元格为横线预留 1px；文章标题使用自身底边框，长标题自然换行，不再计算补白。文章标题无目录按钮时保留 52px 下间距，有按钮时由工具区管理后续间距；正文段落和内部标题层级不变。

“目录与信息”按钮在标题下右对齐，自然占一行，与分隔线间隔 `0.08rem`，和列表普通行间距一致。按钮不再设置独立的 44px 高度，背景直接覆盖按钮本身；工具区下方保留 8px 正文间距。

正文内容边缘到辅助列共用 `--page-shell-gap-inline: 1rem`（默认 15px），这份空间包含滚动条。正文容器宽度为正文宽度加一份间距，辅助列抵消网格原本追加的间距；长文章、短文章和覆盖式滚动条都保留同一份空间。`scrollbar-gutter: stable` 稳定原生占位，正文最大宽度限制在可用空间内；系统滚动条若宽于 1rem，则允许间距随之加宽，避免裁切。集合表格沿用按内容撑宽和外部间距；打印移除正文滚动条预留空间及辅助列偏移。

回归保留无头 Chromium 的原生滚动条，检查调整宽度、滚动、停止和无须滚动时的正文到辅助列距离及横向溢出。不能只测容器外部的网格 gap，也不能用默认隐藏滚动条的浏览器代替占位式滚动条验证。

当前章节用既有 `.is-current` 及 `aria-current="location"` 表示。滚动只更新章节状态，不自动滚动侧栏、不改变 URL。打印隐藏章节导航，元信息排在正文之后。

## 原生锚点实验与明确取舍

真实站点 `swaw-kit-git`、390 / 1024 / 1800px、Chromium 和 WebKit 的实验发现：

1. 纯 HTML 目录可以正确跳到正文标题。
2. Chromium 点击章节后刷新，会把正文独立滚动容器恢复到顶部；此问题在禁用 JavaScript 时仍可复现。
3. WebKit 在 1024px 从右列点击章节，可能只显示正文的一部分，左侧仍在屏幕外。
4. 带 hash 的页面在离开后返回，浏览器不能一致恢复离开时的精确阅读位置。无脚本实验中 Chromium 回顶部，WebKit 回章节开头。

本试验采用单一、无持久状态的章节定位契约：**带章节 hash 的地址在进入、刷新、返回和前进时定位该章节；无 hash 的页面沿用已有画布行为。** 目录点击继续使用真实链接及浏览器 hash 历史，不写 `history.state`、localStorage 或 sessionStorage。脚本只补充完整正文列的显现及当前章节标记。

精确恢复“离开时读到章节中间哪一行”不属于本试验。如果需要，该能力应在画布导航层统一设计，并覆盖同文档 hash 历史和跨文档历史，不能继续在 TOC 中堆补丁。当前脚本在没有 JavaScript 时退化为可用的原生链接，上述浏览器差异仍存在。

## 验证

`document-aside-navigation` 覆盖三语言标题 ID／顺序／文字一致性、H2/H3 平铺列表、文章开头及导语选中、返回顶部及刷新、分类祖先链接与目录顺序、平台图标、日期分行及 clock 图标、元信息等间距与无整行悬停背景、三种宽度的点击／刷新／返回定位、当前章节、侧栏滚动独立性、大小写不同的 URL 转义、无标题文章、无脚本链接和打印。

配合 `canvas-document-aside`、滚动归属、真实触摸横移、普通历史恢复、锚点和键盘顺序回归。正式采用前应由用户实际体验横向移动距离及长章节列表的密度；这属于布局选择，不需要引入新架构。

本次基线审查修复了浏览器回归筛选器静默忽略未知场景名的问题；错误场景名现在在启动浏览器之前失败。基线通过分类集合契约、导航状态、预取策略、祖先标题增量构建、相关浏览器回归和 132 页 HTML 审计。

试验阶段验证了 7 个 Chromium 场景及 6 个 WebKit 场景；WebKit 还暴露了 `pageshow` 之后才完成原生位置恢复的时序问题，章节显现因此安排在下一绘制帧。最终章节用例重跑通过，最终构建的 132 页 HTML 审计通过。章节脚本生产压缩后为 1511 字节，只在有章节导航的文章上加载。
